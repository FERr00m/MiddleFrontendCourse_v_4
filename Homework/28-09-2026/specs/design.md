# Запись к врачу — дизайн функционала

Дизайн описывает поведение и границы фронтенда мастера записи в «Клинику на Лесной». Он закрывает наблюдаемые требования и записанные ответы на OQ-12, OQ-13, OQ-15 и OQ-16. Новых продуктовых сценариев здесь нет.

Пациент без учётной записи проходит четыре шага: «Врач», «Дата», «Время», «Данные». Экран успеха заменяет мастер. Один проход создаёт одну запись.

## Какие требования закрывает дизайн

Дизайн покрывает FR-01 … FR-41. Трассировка — в последнем разделе. Каждое FR сопоставлено разделу ниже.

Закрытые решения, на которые опирается дизайн:

| Вопрос | Ответ, который выполняет дизайн |
| --- | --- |
| OQ-12 | В доступном имени одна причина. Порядок: соседний месяц; день уже прошёл; день за горизонтом; врач не ведёт приём; все окна заняты; правило 2 часов. |
| OQ-13 | Будущий день, у которого свободные окна есть, но ни одно не проходит правило 2 часов, нельзя активировать. В имени дата и текст, что подходящих окон нет, потому что их начало раньше чем через 2 часа. Формулировок «на сегодня» и «все окна заняты» в этом имени нет. |
| OQ-15 | В списке дня только подходящие слоты. Занятые окна в список не входят. |
| OQ-16 | Открываются только месяцы, в которые попадает хотя бы один день горизонта. Переход за эту границу не активируется и имеет текстовую причину. |

Порядок пунктов в списках специальностей и врачей — порядок справочника фикстуры. Дополнительных сведений о враче на экране нет: пациент видит имя и, если окон в горизонте нет, текст состояния. Поле ближайшего свободного начала источник отдаёт, экран его не показывает.

Цвет, шрифт, отступы и точные размеры этот дизайн не задаёт. Различие состояний держится на тексте.

## Технические ограничения

- Vue 3, Composition API, `<script setup lang="ts">`, сборка Vite.
- Стили: CSS Modules, в однофайловом компоненте блок `<style module>`. Готовый UI-kit не подключается.
- Календарь собран из кнопок дней. Не подключаются vue-cal, FullCalendar и нативный `input type="date"`.
- Состояние мастера — одно реактивное состояние страницы: composable `useAppointmentWizard` на `reactive`. Корневой компонент только подключает его. Pinia, Vuex, Redux, Zustand и синхронизация шага с адресом страницы не используются. `localStorage` и `sessionStorage` не читаются и не пишутся.
- Компоненты шагов не импортируют мок, не импортируют модуль `api` и не вызывают `fetch`.
- Запросы выполняет модуль `api`. В этой версии это мок: каждый метод возвращает `Promise`, ждёт 400 мс и читает расписание, один раз собранное из зерна 28. Повторный пересчёт Vue это расписание не пересобирает.
- Чистые функции месяца, горизонта, правила 2 часов и группировки слотов лежат вне Vue и вне `api`. Им передают уже известные данные, включая время клиники. Браузер им не нужен.
- Тесты этой версии — Vitest и только эти чистые функции. Компонентные и сквозные тесты в дизайн не входят.
- Рабочие ширины: 320 и 1280. Между ними сетка остаётся семью равными колонками. Отдельных макетов промежуточных ширин нет.
- Время правил — Europe/Moscow. Момент читается один раз в начале прохода и кладётся в состояние. «Записать ещё» начинает новый проход и читает момент заново. Перезагрузка страницы уничтожает состояние и читает момент заново.

## Поток мастера

Оболочка на шагах показывает название «Клиника на Лесной», адрес «Москва, ул. Лесная, 7» и четыре названия шагов. Текущий шаг отмечен текстом и `aria-current="step"`. Названия шагов не являются кнопками: вперёд переводит только действие шага, назад — кнопка «Назад».

Черновик живёт в памяти прохода: специальность, врач, день, слот и поля пациента. Смена специальности очищает врача, день и слот. Смена врача очищает день и слот. Фамилия, имя, телефон, тип визита, комментарий и согласие при этих сменах остаются. Перезагрузка страницы поднимает новый проход с пустым черновиком. Значения из адреса и из хранилища браузера в черновик не подставляются.

### Шаг «Врач»

Пациент видит список специальностей, а после выбора специальности — список врачей этой специальности. Пункта «любой врач» нет. Кнопки «Назад» нет.

Вперёд со специальности: пациент активирует специальность. Шаг остаётся «Врач», под списком специальностей появляется блок врачей. Вперёд с врача: пациент активирует врача, у которого в горизонте есть свободное окно. Открывается шаг «Дата».

Повторная активация уже выбранной специальности врача, день и слот не очищает и второй запрос той же специальности не отправляет. Активация другой специальности очищает врача, день и слот, поля пациента оставляет и запрашивает врачей новой специальности.

Врач без свободного слота в горизонте остаётся в списке. Активировать его нельзя. Рядом виден текст «Нет окон в ближайшие 3 недели».

Уже выбранные данные остаются: выбранная специальность; врач, если его не сбросила смена специальности; день и слот, если врач не менялся; все поля пациента.

### Шаг «Дата»

Пациент видит пояснение «Время московское (Europe/Moscow)», месяц и сетку календаря выбранного врача. Расписание — этого врача, не смесь врачей.

Вперёд: активация дня отображаемого месяца, у которого есть хотя бы один подходящий слот. Открывается шаг «Время». Активация другого дня очищает слот. Повторная активация того же дня слот оставляет и снова открывает шаг «Время». Запись при этом не создаётся.

«Назад» открывает шаг «Врач». Специальность, врач, день, слот и поля пациента остаются. Календарь без врача по-прежнему недоступен, потому что врач в черновике есть: шаг «Дата» снова откроется только активацией врача.

При первом входе на шаг показан месяц текущей даты клиники. Если день уже выбран, показан месяц этого дня. Смена месяца день не выбирает и выбранный день не очищает.

### Шаг «Время»

Пациент видит «Время московское (Europe/Moscow)», «Приём длится 30 минут» и подходящие слоты выбранного дня выбранного врача. Время начала имеет вид «09:30». Занятых слотов в списке нет.

Вперёд: активация слота записывает его начало в черновик и открывает шаг «Данные». Повторная активация того же слота тоже только открывает шаг «Данные». `createAppointment` при выборе слота не вызывается.

«Назад» открывает шаг «Дата». Слот, день, врач, специальность и поля пациента остаются.

### Шаг «Данные»

Пациент видит фамилию, имя, телефон, тип визита, комментарий, согласие с подписью и пометкой про политику, кнопку «Записаться». Тип визита на слоты, длительность и календарь не влияет. Цены нет.

Вперёд: «Записаться» при валидных полях и данном согласии один раз отправляет создание записи. Успешный ответ открывает экран успеха.

«Назад» открывает шаг «Время». Поля пациента и выбранный слот остаются.

Пока создание выполняется, второе нажатие «Записаться» второй запрос не отправляет.

### Экран успеха

Успешный ответ заменяет мастер. Списка шагов на экране нет, пятым шагом успех не считается. Кнопки «Назад» нет. Вернуться к заполненной форме нельзя.

Пациент видит заголовок «Вы записаны», специальность, врача, дату вида «30 сентября, среда», время вида «09:30», тип визита, «Клиника на Лесной», «Москва, ул. Лесная, 7» и текст «Чтобы перенести или отменить запись, позвоните в регистратуру: +7 (495) 000-00-00». Номер — ссылка `tel:+74950000000`. Цены нет. Отмены и переноса в интерфейсе нет.

«Записать ещё» уничтожает черновик прохода и открывает шаг «Врач» заново: специальность, врач, день, слот, фамилия, имя, телефон, тип визита, комментарий и согласие пустые. Занятость слота, созданная прошлой записью, в памяти мока сохраняется до перезагрузки страницы. Новый проход может создать ещё одну запись, в том числе к тому же врачу.

## Состояния шагов

У каждого состояния есть условие входа и то, что видно пациенту. Текстовое состояние выполнения стоит в том блоке, который ещё не получил данные. Отдельного индикатора без текста нет.

Общие правила запроса:

- Пока статус этого запроса `loading` или создание в статусе `submitting`, повторный запуск того же действия выходит сразу и модуль `api` не вызывается.
- Ответ применяется, только если идентификатор специальности, врача или дня в ответе совпадает с черновиком на момент ответа.
- Ошибка загрузки показывает свой текст и кнопку повтора. Пустой список на её месте не рисуется. Текст «Врач в этот день не ведёт приём» и «Все окна заняты» на месте ошибки загрузки не используется.

## Календарь

Календарь получает готовую модель месяца и рисует её. Он не вызывает `api`, не вычисляет горизонт, не классифицирует день и не решает, когда запрашивать расписание. Модель собирает composable чистой функцией `buildMonthModel`.

### Сетка

Один отображаемый месяц. Колонки с понедельника по воскресенье. В сетке видны дни соседних месяцев, которыми начинается первая неделя и заканчивается последняя. Число недель — от 4 до 6: от понедельника накануне или в день 1-го числа до воскресенья последнего дня месяца. Пустая шестая неделя не добавляется.

Подписи колонок:

- ширина от 1280 px — «понедельник» … «воскресенье»;
- ширина меньше 1280 px, включая 320, — «Пн», «Вт», «Ср», «Чт», «Пт», «Сб», «Вс».

Доступное имя колонки в обоих случаях полное: «понедельник» … «воскресенье». На 320 семь колонок делят ширину контейнера поровну (`repeat(7, minmax(0, 1fr))`) и не создают горизонтальную прокрутку месяца.

Заголовок месяца: название в именительном падеже и год, например «сентябрь 2026».

### Границы листания

Горизонт: от текущей даты клиники включительно до этой даты плюс 21 календарный день включительно. Пример из требований: 28 сентября 2026 → последняя дата 19 октября 2026. 20 октября 2026 за горизонтом.

Месяц можно показать, если хотя бы один его день входит в горизонт. Из этого следуют границы кнопок и клавиш PageUp и PageDown:

- нельзя открыть месяц раньше месяца текущей даты клиники;
- нельзя открыть месяц позже месяца, в котором лежит последний день горизонта.

Кнопки «Предыдущий месяц» и «Следующий месяц» на границе остаются в порядке фокуса, имеют `aria-disabled="true"` и видимую причину: «Месяц раньше горизонта записи» или «Месяц позже горизонта записи». Активация такой кнопки месяц не меняет. Пока месяц внутри границ, причина скрыта, кнопка активируется.

Смена месяца меняет только отображаемый месяц. Выбранный день в черновике не меняется, новый день сам не выбирается. Если выбранная дата попала в новую сетку, ячейка этой даты отмечена выбранной. Если не попала, выбранной ячейки в сетке нет, дата в черновике остаётся.

### Как считается день

Входы классификации: дата ячейки, принадлежит ли она отображаемому месяцу, сегодняшняя дата клиники, горизонт, текущие минуты клиники, окна этой даты у выбранного врача (начало и признак занятости). Окна другого врача в расчёт не входят.

Одна причина по порядку OQ-12. Первая выполнившаяся условие и есть причина.

| Проверка по порядку | Причина | Текст состояния в доступном имени |
| --- | --- | --- |
| Дата не в отображаемом месяце | Соседний месяц | День соседнего месяца |
| Дата раньше сегодняшней даты клиники | День уже прошёл | День уже прошёл |
| Дата позже последней даты горизонта | День за горизонтом | День за горизонтом 21 дня |
| Окон нет: ни свободных, ни занятых | Врач не ведёт приём | Врач в этот день не ведёт приём |
| Окна есть, свободных нет | Все окна заняты | Все окна заняты |
| Свободные окна есть, подходящих нет, дата — сегодня | Сегодня и правило 2 часов | На сегодня подходящих окон больше нет, потому что оставшиеся слоты начинаются раньше чем через 2 часа |
| Свободные окна есть, подходящих нет, дата позже сегодня | Будущий день и правило 2 часов | Подходящих окон нет, потому что их начало раньше чем через 2 часа |

Если часть окон занята, а оставшиеся свободные не проходят правило 2 часов, причина — правило 2 часов, не «все окна заняты».

День отображаемого месяца внутри горизонта можно активировать, когда подходящих слотов хотя бы один. Такой день не получает причину недоступности.

Отдельные признаки, которые причиной недоступности не являются:

- **Сегодня** — дата ячейки равна текущей дате клиники в Europe/Moscow. Сегодняшний день может быть доступен или недоступен по таблице выше.
- **Выбранный день** — дата ячейки равна дате в черновике. Выбор возможен только активацией доступного дня отображаемого месяца. Смена месяца и фокус выбор не ставят.
- **Прошедший день, день за горизонтом, выходной врача, день без окон, день только со слишком близкими слотами, день соседнего месяца** — строки таблицы выше. «Выходной врача» и «день без окон» — одна причина «врач не ведёт приём»: на дату нет ни свободных, ни занятых окон.

Под сеткой видна строка состояния дня, на котором стоит фокус. Её текст совпадает с доступным именем этого дня. Строка для зрения; у вспомогательной технологии имя берётся с кнопки дня, поэтому строка помечена `aria-hidden="true"`.

### Доступное имя дня

Имя собирает чистая функция, календарь его не склоняет заново.

1. Дата вида «28 сентября, понедельник».
2. Если дата — сегодня клиники, дальше слово «сегодня».
3. Если дата равна выбранной, дальше слово «выбран».
4. Состояние: одна формулировка из таблицы либо, для доступного дня, «Можно записаться».
5. Если подходящих слотов больше нуля, в конце «Свободных слотов: N». У недоступного дня числа нет.

Примеры:

- Доступный день: «30 сентября, среда. Можно записаться. Свободных слотов: 4.»
- Сегодня, доступный и выбранный: «28 сентября, понедельник, сегодня, выбран. Можно записаться. Свободных слотов: 2.»
- Соседний месяц: «1 октября, четверг. День соседнего месяца.»
- Прошедший: «4 марта, среда. День уже прошёл.»
- За горизонтом: «27 марта, пятница. День за горизонтом 21 дня.»
- Нет окон: «6 марта, пятница. Врач в этот день не ведёт приём.»
- Все заняты: «9 марта, понедельник. Все окна заняты.»
- Сегодня и правило 2 часов: «28 сентября, понедельник, сегодня. На сегодня подходящих окон больше нет, потому что оставшиеся слоты начинаются раньше чем через 2 часа.»
- Будущий день и правило 2 часов: «29 сентября, вторник. Подходящих окон нет, потому что их начало раньше чем через 2 часа.»

Активация недоступного дня дату в черновике не меняет и шаг не меняет.

## Слоты

Источник дня отдаёт все окна даты с признаком занятости. До экрана их пропускает чистая функция `suitableSlots`, затем `groupSlots`. Компонент шага получает уже сгруппированный список и рисует его одной группой `radiogroup` с именем «Свободное время». Заголовки «Утро», «День» и «Вечер» — группы внутри неё, не отдельные радиогруппы. У всех радиокнопок одно `name`.

Подходящий слот: окно свободно, дата начала в горизонте, начало не раньше текущего времени клиники плюс 2 часа. Равенство двух часов подходит. Сравнение идёт по абсолютным московским минутам, поэтому слот следующих суток тоже отсекается, если до него меньше двух часов. При начале окон с 09:00 это видно только если текущее время клиники позже 07:00 тех суток, куда попадает слот.

Занятый слот в разметку не попадает, активировать его нельзя. Слот с началом 13:00 или 13:30 генератор не создаёт. Начало вне трёх интервалов группировки функция в группы не кладёт, и пациент его не видит.

Границы групп по времени начала, границы включены:

| Группа | Начало |
| --- | --- |
| Утро | 09:00 … 12:30 |
| День | 14:00 … 15:30 |
| Вечер | 16:00 … 17:30 |

Пустая группа не показывается. Непустые идут в порядке «Утро», «День», «Вечер». Внутри группы начала возрастают. Подпись радиокнопки — начало вида «09:30». Длительность на кнопке не дублируется: она указана строкой «Приём длится 30 минут». Тип визита в отбор и группировку не передаётся.

Активация радиокнопки записывает начало в черновик и переводит на шаг «Данные». Повторная активация уже выбранного начала делает только этот переход. Запись создаёт только «Записаться».

## Форма

Поля и только они: фамилия, имя, телефон, тип визита, комментарий, согласие. Ошибка появляется в момент нажатия «Записаться», если поле не проходит правило. До этого нажатия ошибки поля нет. Повторное нажатие собирает ошибки заново: у прошедшего поля ошибка снимается, у непрошедшего остаётся. Правка между нажатиями текст ошибки не скрывает.

Проверку выполняет чистая функция `validatePatient`. Шаг показывает возвращённые ошибки и сам правила не хранит. Если есть хотя бы одна ошибка, `createAppointment` не вызывается.

У ошибки есть элемент с `id`. Поле с ошибкой: `aria-invalid="true"` и `aria-describedby` на этот `id`. Без ошибки: `aria-invalid="false"`, ссылки на ошибку нет. У согласия `aria-describedby` всегда включает пометку о политике и добавляет ошибку, когда она есть.

Порядок фокуса при ошибках: фамилия, имя, телефон, тип визита, комментарий, согласие. Фокус ставится на первое поле из этого списка, у которого есть ошибка. Остальные ошибки тоже видны.

| Поле | Правило | Момент ошибки | Текст ошибки |
| --- | --- | --- | --- |
| Фамилия | Обязательна. От 2 до 40 символов Юникода включительно. Каждый символ — буква кириллицы (`Script=Cyrillic`), дефис `-` или пробел. «ё» и «Ё» допустимы. | Нажатие «Записаться», если правило не выполнено. | Укажите фамилию: от 2 до 40 символов, кириллица, дефис или пробел. |
| Имя | То же правило, что у фамилии. | То же нажатие. | Укажите имя: от 2 до 40 символов, кириллица, дефис или пробел. |
| Телефон | Обязателен. Строка целиком совпадает с `+7`, затем `9`, затем ещё 9 цифр: `^\+79\d{9}$`. | То же нажатие. | Укажите телефон: +7 и 10 цифр, первая из них 9. |
| Тип визита | Обязателен. Значение «Первичный» или «Повторный». По умолчанию не выбран. На слоты, длительность и календарь не влияет. | То же нажатие, если значение не выбрано. | Выберите тип визита: первичный или повторный. |
| Комментарий | Необязателен. Пустая строка допустима. Длина не больше 300 символов Юникода. | То же нажатие, если длина больше 300. У пустого и короткого комментария ошибки нет. | Комментарий не длиннее 300 символов. |
| Согласие | Обязательно. Подпись: «Соглашаюсь на обработку персональных данных для записи на приём». Рядом статичная пометка «Текст политики в этой версии не подключён». Ссылки на политику нет. Пока согласие не дано, запрос создания не уходит. | То же нажатие, если флажок выключен. | Нужно согласие на обработку персональных данных. |

Запись создаётся на одну фамилию и одно имя из этих полей. Отдельных полей ребёнка, родственника и филиала нет.

## Успех, конфликт времени, ошибки загрузки

Модуль `api` возвращает размеченное состояние. Экран смотрит на него и не угадывает исход по пустому массиву и не по тексту исключения.

| Исход | Кто возвращает | Что происходит |
| --- | --- | --- |
| Успех создания | `createAppointment` → `success` | Мастер заменён экраном успеха. Фокус на заголовке «Вы записаны». |
| Слот занят | `createAppointment` → `slot-taken` | Запись не создана. Шаг «Время» того же врача и того же дня. Начало слота в черновике очищено. Слоты дня запрашиваются заново. Виден текст «Это время только что заняли. Выберите другое.» Поля пациента сохраняются. Фокус на этом тексте. |
| Отказ создать запись | `createAppointment` → `rejected` | Пациент остаётся на шаге «Данные». Виден текст «Запись не создана.» Фокус на этом тексте. Поля и выбранный слот сохраняются. После завершения запроса «Записаться» можно нажать снова: это уже новый запрос. |
| Ошибка загрузки создания | `createAppointment` → `load-error` | Пациент остаётся на шаге «Данные». Виден текст «Не удалось отправить запись.» и кнопка повтора. Фокус на тексте ошибки. Повтор после завершения ошибки снова вызывает создание. Пока запрос идёт, повтор второй вызов не делает. |
| Ошибка загрузки списков и календаря | методы чтения → `load-error` | Текст ошибки и повтор стоят вместо того блока, который запрашивался. |
| Пустой ответ | методы чтения → `empty` | Текст пустого состояния вместо того же блока. Ошибки загрузки нет. |

Пока идёт создание, надпись кнопки — «Создаём запись». Второй запуск того же действия не создаёт вторую запись.

Текст регистратуры на успехе статичный. Отдельного сценария звонка нет: достаточна ссылка на номер.

## Модули и компоненты

Зависимости идут в одну сторону: компоненты → composable → `api` и чистые функции. Чистые функции не импортируют Vue и `api`. `api` может вызывать чистые функции, чтобы признак окон врача считался тем же правилом, что и календарь.

| Модуль | Чем владеет | Чего не делает |
| --- | --- | --- |
| `src/domain/clinic-time.ts` | Перевод момента в московскую дату и минуты, сдвиг календарной даты, формат «28 сентября, понедельник» и «09:30». | Не читает часы сам, не ходит в сеть, не знает про шаг мастера. |
| `src/domain/horizon.ts` | Границы горизонта и проверка, что дата внутри. | Не решает, какой месяц открыт. |
| `src/domain/slots.ts` | Правило 2 часов и группировка подходящих слотов. | Не скрывает занятые окна за цветом и не создаёт запись. |
| `src/domain/month.ts` | Сетка до 6 недель, порядок причин, доступное имя, границы листания, подписи дней недели. | Не вызывает `api` и не выбирает день при смене месяца. |
| `src/domain/patient-fields.ts` | Правила полей и тексты их ошибок. | Не решает, когда показать ошибку: момент задаёт composable, это нажатие «Записаться». |
| `src/content/texts.ts` | Остальные строки таблицы текстов. | Не содержит правил дня и валидации. |
| `src/api/index.ts` | Единственный исполнитель запросов. Методы, задержка 400 мс, результаты успеха, пустого ответа, ошибки загрузки, отказа и занятого слота. | Не меняет шаг, не рисует календарь, не проверяет фамилию. |
| `src/api/schedule.ts` | Память расписания на жизнь страницы: генерация из зерна 28 и отметка занятого окна после успешной записи. | Не импортируется компонентами. |
| `src/wizard/useAppointmentWizard.ts` | Единственное реактивное состояние, переходы шагов, решение когда звать `api`, защита от повторного запроса, сборка модели месяца и групп слотов. | Не содержит разметки. |
| `AppointmentWizard.vue` | Оболочка: клиника, список шагов, выбор экрана по состоянию, перенос фокуса при смене шага. | Не импортирует мок и `api`. |
| `DoctorStep.vue` | Разметка специальностей и врачей. | Не загружает списки. |
| `DateStep.vue` | Пояс, «Назад», размещение календаря и строки загрузки, пустого ответа и ошибки дней. | Не строит сетку. |
| `CalendarMonth.vue` | Рисует готовую модель месяца и отдаёт события клавиатуры и активации. | Не решает, когда вызывать `api`, и не назначает причину дня. |
| `TimeStep.vue` | Пояс, длительность, сообщение конфликта, одна радиогруппа слотов. | Не группирует интервалы и не создаёт запись. |
| `PatientStep.vue` | Поля, связь ошибки с полем, кнопка «Записаться». | Не проверяет символы сама: показывает ошибки, которые пришли в props. |
| `SuccessScreen.vue` | Экран успеха и «Записать ещё». | Не хранит черновик и не возвращает форму. |

Владелец запросов — `src/api/index.ts`. Composable — единственный, кто его вызывает. Календарь запрос не начинает: смена месяца только меняет поле отображаемого месяца, а модель пересобирается из уже полученных дней.

Состояние composable:

- шаг: `doctor`, `date`, `time`, `patient` или экран `success`;
- черновик;
- момент клиники этого прохода;
- отображаемый месяц;
- статусы запросов специальностей, врачей, дней и слотов: `loading`, `ready`, `empty`, `load-error`;
- статус создания: `idle`, `submitting`, `rejected`, `load-error`;
- флаг сообщения о занятом слоте;
- ошибки полей;
- созданная запись для экрана успеха.

Начальное состояние прохода: шаг `doctor`, все идентификаторы черновика пустые, поля пациента пустые, тип визита не выбран, согласие выключено, статусы создания `idle`, запись успеха отсутствует. Composable в том же запуске переводит специальности в `loading` и вызывает `listSpecialties`.

## Модель данных

Типы ниже — контракт между чистыми функциями, `api` и состоянием. Компоненты получают уже собранные надписи и флаги, не сырые окна.

```ts
type IsoDate = string // YYYY-MM-DD, календарная дата Europe/Moscow
type TimeHm = string // HH:mm, 24 часа, час и минуты из двух цифр

type ClinicDateTime = {
  date: IsoDate
  minutes: number // 0..1439 от полуночи Europe/Moscow
}

type Specialty = {
  id: string
  name: string
}

type Doctor = {
  id: string
  specialtyId: string
  name: string
  hasFreeWindowInHorizon: boolean
  nearestFreeStart: { date: IsoDate; time: TimeHm } | null
}

type WindowSlot = {
  start: TimeHm
  busy: boolean
}

type DayWindowSummary = {
  date: IsoDate
  slots: WindowSlot[]
}

type DayUnavailabilityReason =
  | "adjacent-month"
  | "past"
  | "beyond-horizon"
  | "no-windows"
  | "all-booked"
  | "too-soon-today"
  | "too-soon-future"

type DayAvailability =
  | {
      date: IsoDate
      selectable: true
      freeSlotCount: number
    }
  | {
      date: IsoDate
      selectable: false
      reason: DayUnavailabilityReason
      freeSlotCount: null
    }

type CalendarDay = {
  date: IsoDate
  inDisplayedMonth: boolean
  isToday: boolean
  isSelected: boolean
  availability: DayAvailability
  accessibleName: string
}

type MonthModel = {
  label: string
  weeks: CalendarDay[][] // 4..6 недель, в каждой 7 дней, понедельник первый
  canGoToPreviousMonth: boolean
  canGoToNextMonth: boolean
  previousMonthDeniedReason: string | null
  nextMonthDeniedReason: string | null
}

type Slot = {
  doctorId: string
  date: IsoDate
  start: TimeHm
}

type SlotGroupId = "morning" | "afternoon" | "evening"

type SlotGroup = {
  id: SlotGroupId
  title: "Утро" | "День" | "Вечер"
  slots: Slot[]
}

type VisitType = "primary" | "follow-up"

type PatientFields = {
  lastName: string
  firstName: string
  phone: string
  visitType: VisitType | null
  comment: string
  consent: boolean
}

type AppointmentDraft = {
  specialtyId: string | null
  doctorId: string | null
  date: IsoDate | null
  slotStart: TimeHm | null
  patient: PatientFields
}

type Appointment = {
  id: string
  specialtyName: string
  doctorName: string
  date: IsoDate
  time: TimeHm
  visitType: VisitType
}
```

`DayUnavailabilityReason` различает все причины DR-08, включая будущий день, у которого свободные окна есть, но ни одно не проходит правило 2 часов. День соседнего месяца — тоже значение этой суммы, даже когда сырой источник про соседний месяц ничего не говорит: признак `inDisplayedMonth` задаёт сетка.

`nearestFreeStart` равен `null`, когда `hasFreeWindowInHorizon` ложно. Экран это поле не показывает.

`Appointment` не содержит цену. На экране успеха имя пациента не показывается: подтверждаются специальность, врач, дата, время и тип визита.

### Входы и выходы чистых функций

`clinicDateTime(parts)` принимает год, месяц, день, часы и минуты уже в Europe/Moscow и возвращает `ClinicDateTime`. Разбор часового пояса устройства делает только оболочка в момент старта прохода и передаёт сюда готовые московские части. Функция сама часы не читает.

`addCalendarDays(date, days)` возвращает календарную дату через `days` дней. Горизонт — `addCalendarDays(today, 21)`.

`formatClinicDate(date)` возвращает «28 сентября, понедельник». `formatTime(minutes)` возвращает «09:30».

`bookingHorizon(today)` возвращает `{ start: today, end: addCalendarDays(today, 21) }`. Дата D внутри, если `start <= D <= end`.

`isSuitableSlot(slot, now, horizon)` принимает `{ date, start, busy }` и возвращает boolean. Истина, когда `busy` ложно, дата в горизонте и московские минуты начала больше либо равны минутам `now` плюс 120.

`suitableSlots(slots, now, horizon)` возвращает только подходящие `Slot` по возрастанию начала.

`groupSlots(slots)` принимает уже подходящие слоты одного дня и возвращает `SlotGroup[]` без пустых групп. Начало 13:00 и 13:30, как и любое начало вне трёх интервалов, в результат не входит.

`buildMonthModel({ displayedMonth, today, horizon, now, selectedDate, days })` принимает номер месяца, сырые `DayWindowSummary[]` выбранного врача и возвращает `MonthModel`. Дата без записи в `days` считается днём без окон. Функция не меняет `selectedDate`.

`weekdayHeader(index, mode)` принимает индекс 0…6 от понедельника и режим `wide | narrow`. `wide` — полное имя, `narrow` — «Пн»…«Вс».

`validatePatient(fields)` возвращает список `{ field, message }` в порядке фокуса. Пустой список означает, что создание разрешено правилами полей.

Эти функции можно вызвать из Vitest с фиксированными `ClinicDateTime` из сценариев, без монтирования Vue. В тесты этой версии входят горизонт, правило 2 часов, группировка и модель месяца, включая порядок причин и доступное имя. `validatePatient` чистая и лежит рядом, но в набор тестов этой версии не входит.

## Контракт api

Методы — функции модуля, не обязательный HTTP. Календарь и шаги завязаны на эти результаты. Замена мока на HTTP повторяет те же функции и те же статусы и не переписывает сетку.

Общая форма чтения:

```ts
type ReadResult<T> =
  | { status: "success"; data: T }
  | { status: "empty" }
  | { status: "load-error" }
```

Пустой ответ — успешное получение, в котором нет ни одного пункта. Это отдельный статус, не пустой массив внутри `success` и не ошибка загрузки.

```ts
type CreateResult =
  | { status: "success"; appointment: Appointment }
  | { status: "slot-taken" }
  | { status: "rejected" }
  | { status: "load-error" }
```

| Метод | Аргументы | Успех | Пустой ответ | Ошибка загрузки | Отказ «слот занят» |
| --- | --- | --- | --- | --- | --- |
| `listSpecialties` | нет | `{ status: "success", data: Specialty[] }` в порядке справочника | `{ status: "empty" }` | `{ status: "load-error" }` | нет |
| `listDoctors` | `specialtyId`, `now` | `{ status: "success", data: Doctor[] }` только этой специальности, с `hasFreeWindowInHorizon` и `nearestFreeStart` | `{ status: "empty" }` | `{ status: "load-error" }` | нет |
| `getDoctorDays` | `doctorId`, `from`, `to` | `{ status: "success", data: DayWindowSummary[] }` по датам интервала, где есть хотя бы одно окно | `{ status: "empty" }`, если в интервале нет ни одного окна | `{ status: "load-error" }` | нет |
| `getDaySlots` | `doctorId`, `date` | `{ status: "success", data: WindowSlot[] }` все окна даты, и свободные, и занятые | `{ status: "empty" }`, если окон даты нет | `{ status: "load-error" }` | нет |
| `createAppointment` | врач, дата, начало, поля пациента с `consent: true` и выбранным типом визита | `{ status: "success", appointment }` | нет: создание не список | `{ status: "load-error" }` | `{ status: "slot-taken" }`, если окно к моменту вызова занято. Иной отказ источника — `{ status: "rejected" }` |

`from` и `to` для дней — начало и конец горизонта включительно. Смена месяца этот метод не вызывает.

Мок перед ответом ждёт 400 мс. Расписание одного открытия страницы хранится в модуле `schedule`. Успешное создание помечает окно занятым. Следующий `getDaySlots` той же страницы возвращает его занятым, и повторное создание на то же начало возвращает `slot-taken`. Перезагрузка собирает расписание из зерна заново, без этой пометки.

В этой версии мок по умолчанию проходит успешный путь фикстуры. Ветки `empty`, `load-error`, `rejected` и `slot-taken` заданы контрактом, чтобы экран был тот же при удалённом источнике. Мок возвращает `slot-taken`, когда запрошенное окно уже занято в его памяти.

## Адаптив

Один вертикальный мастер на 320 и на 1280. Меняются подписи дней недели и перенос строк, не состав шагов.

На 320 и на 1280 видны шаги «Врач», «Дата», «Время», «Данные», путь доходит до экрана успеха, успех не становится пятым шагом, на шаге «Врач» нет «Назад». На 320 семь дней недели помещаются в сетку без горизонтальной прокрутки месяца.

Ширина от 1280 px включает полные подписи колонок. Меньшая ширина, включая 320, включает короткие. Промежуточные ширины отдельно не описываются: колонки остаются семью долями контейнера, длинные русские строки переносятся внутри своих блоков.

## Клавиатура и доступность

Язык страницы — русский (`lang="ru"`). Путь от списка специальностей до экрана успеха проходит без указателя: Tab переносит фокус, Enter и Пробел активируют кнопку, флажок и выбранную радиокнопку.

Специальности — одна радиогруппа. Врачи — кнопки. Врач без окон фокусируется, у кнопки `aria-disabled="true"` и доступное имя из имени врача и текста «Нет окон в ближайшие 3 недели». Enter и Пробел на ней врача не выбирают. Атрибут `disabled` не используется, чтобы фокус мог встать на причину.

Календарь — `role="grid"`, имя сетки берётся из заголовка месяца. Один день имеет `tabindex="0"`, остальные `-1`. Стрелки переносят этот фокус на соседний день на 1:

- ArrowLeft и ArrowUp — на один день раньше;
- ArrowRight и ArrowDown — на один день позже.

Если целевого дня в текущей сетке нет, фокус остаётся, месяц стрелками не меняется. Home ставит фокус на понедельник той же недели, End — на воскресенье той же недели, включая дни соседнего месяца в этой строке. PageUp и PageDown сдвигают отображаемый месяц на один назад и вперёд, только внутри границ горизонта. Фокус после этого встаёт на число того же дня месяца. Если такого числа в целевом месяце нет, фокус встаёт на последний день целевого месяца внутри сетки. На границе горизонта PageUp или PageDown ничего не меняют, фокус остаётся на прежнем дне.

Фокус можно поставить на недоступный день. Его доступное имя произносит дату и причину. Enter и Пробел на недоступном дне день не выбирают.

Уход фокуса:

- смена шага кнопкой «Назад», активацией врача, дня или слота ставит фокус на заголовок открытого шага;
- ошибка поля после «Записаться» оставляет шаг «Данные» и ставит фокус на первое невалидное поле, у которого выставлены `aria-invalid` и `aria-describedby`;
- сообщение «Это время только что заняли. Выберите другое.» получает фокус сразу после перехода на шаг «Время»;
- ошибка загрузки и отказ «Запись не создана.» получают фокус на своём тексте, кнопка повтора или «Записаться» следуют за ним по Tab;
- экран успеха ставит фокус на «Вы записаны»;
- «Записать ещё» ставит фокус на заголовок шага «Врач»;
- смена месяца кнопкой оставляет фокус на этой кнопке и день не выбирает;
- смена месяца с PageUp и PageDown оставляет фокус внутри сетки на дне целевого месяца и день не выбирает.

Тексты загрузки, пустого ответа, ошибки, отказа, конфликта, врача без окон и ошибок полей доступны как текст, не только как цвет.

Справочник фиксированный. Сценарии требований используют условные имена и этот справочник не заменяют.

| Специальность | id | Врачи |
| --- | --- | --- |
| Терапия | `therapy` | Иванова М. С. (`therapy-1`), Петров А. В. (`therapy-2`), Соколова Н. П. (`therapy-3`) |
| Кардиология | `cardiology` | Орлов Д. И. (`cardiology-1`), Белова К. Е. (`cardiology-2`) |
| Неврология | `neurology` | Морозов И. Л. (`neurology-1`), Волкова А. С. (`neurology-2`), Егоров П. Н. (`neurology-3`), Крылова Т. Д. (`neurology-4`) |
| Оториноларингология | `ent` | Лебедев С. А. (`ent-1`), Фролова О. В. (`ent-2`), Никитин Г. Р. (`ent-3`) |

У каждой специальности от 2 до 4 врачей. Порядок списков — порядок этой таблицы.

### Правило генерации

Зерно `28`. Расписание на интервал горизонта собирается один раз за жизнь страницы функцией `buildSchedule(seed, horizon)` и дальше только меняет признак занятости у созданных записей. Двадцать один день в документе не расписан.

Начала окон рабочего дня, по порядку: 09:00, 09:30, 10:00, 10:30, 11:00, 11:30, 12:00, 12:30, 14:00, 14:30, 15:00, 15:30, 16:00, 16:30, 17:00, 17:30. Начал 13:00 и 13:30 нет.

Суббота и воскресенье у всех врачей без окон.

`Соколова Н. П.` (`therapy-3`) не имеет окон ни на одну дату горизонта. У неё `hasFreeWindowInHorizon` ложно и `nearestFreeStart` равно `null`. Это врач без окон в горизонте, и она остаётся в списке терапии.

Остальным врачам назначается один будний день без приёма. Порядковый номер врача `n` в таблице, начиная с 1. Число:

```ts
mix(28, [n]) % 5 + 1
```

где 1 — понедельник, 5 — пятница. В этот день недели окон нет.

```ts
function mix(seed: number, parts: number[]): number {
  let x = seed >>> 0
  for (const part of parts) {
    x = Math.imul(x ^ (part >>> 0), 1664525) + 1013904223
    x = x >>> 0
  }
  return x
}
```

`dateNumber` — число суток от 2020-01-01 до даты. Окно занято, если

```ts
mix(28, [n, dateNumber, startMinutes]) % 4 === 0
```

Иначе окно свободно. Так часть слотов уже занята, и сдвиг горизонта не перетасовывает прежние даты.

Для врача, которого можно выбрать, — `Иванова М. С.` (`therapy-1`, `n = 1`) — после этого правила два обязательных дня. Рабочий день здесь: дата горизонта, не суббота, не воскресенье и не её будний день без приёма.

- Первый рабочий день горизонта: все 16 окон есть и все заняты. Это полностью занятый день.
- Первый рабочий день строго после текущей даты клиники, отличный от полностью занятого: окно 09:30 существует и свободно, даже если `mix` помечал его занятым. Остальные окна этого дня остаются по `mix`. Это день с окнами. Начало 09:30 на дату позже сегодня подходит по правилу 2 часов при сетке, которая начинается в 09:00.

Остальные врачи со расписанием таких принудительных дней не получают: у них занятость определяет только `mix`, плюс суббота, воскресенье и один будний день без приёма.

`hasFreeWindowInHorizon` и `nearestFreeStart` считаются при `listDoctors` функцией `isSuitableSlot` от `now` прохода. У Ивановой М. С. свободные 09:30 на будущем рабочем дне делают признак истинным.
